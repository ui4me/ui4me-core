# Building and verifying UI4ME Core 1.0.0 Linux distributions

## Scope

Build an actual Linux-native Rust host embedded inside a CPython-independent Python client wheel. This is a pure-Python client plus ELF executable, **not** a Python C extension. The wheel is platform-specific, not universal. Rust is a build-time requirement only; installing the verified wheel must not invoke Cargo. This product does not include a Python interpreter for the user's own application.

**Linux first:** Debian 13 with KDE Plasma 6.3 native Wayland is the release-test system. Windows code remains in source but is not part of this milestone. Do not build or test Windows now.

## Dependencies

- Python 3.10+, `pip`, working virtual environments, `build`, `setuptools`, `wheel`, `twine`, `packaging`, `auditwheel` as needed.
- Pinned Rust 1.99.1 and components `clippy`, `rustfmt`.
- A working linker/toolchain and Linux system development dependencies: `libwayland-dev`, `libxkbcommon-dev`, `libdbus-1-dev`, `pkg-config` plus standard native packaging tools.
- Docker/Podman and a compatible manylinux image for repaired portable wheels. The checked-in GitHub Actions workflow uses manylinux 2.34 x86_64.

## Native source checks

```bash
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo test --locked --workspace -- --test-threads=2
python3 -m unittest discover -s tools -p 'test_*.py'
```

Run all transport/process tests unfiltered: the earlier cloud environment forbids AF_UNIX bind but the local KDE environment does not. Run the full native acceptance suite on installed release binaries as instructed in `LOCAL_FINISH_PROMPT.md`.

## Local native Linux wheel and sdist

```bash
bash tools/release/build_linux.sh
```

This builds `dist/ui4me_core-1.0.0.tar.gz`, then builds the platform-specific wheel `ui4me_core-1.0.0-py3-none-linux_x86_64.whl` **from that sdist** (proving the source archive is a complete build input), validates metadata with `twine check` and `tools/release/verify_linux_artifact.py`, and **never uploads** them. The wheel embeds the host, `ui4me_core/_bin/THIRD_PARTY_LICENSES.txt` (license texts of every Rust package linked into it, generated by `tools/release/collect_licenses.py`) and the project, font and MPL license files. That locally tagged wheel is suitable for testing on matching Linux distributions, but is **not** a PyPI-ready portable wheel. Platform wheels may depend on glibc and other dynamically linked libraries; verify their `ldd` output.

## Public-wheel build

Trigger `.github/workflows/release-linux.yml` using `workflow_dispatch` after the Linux source is qualified, or build the same image locally from the sdist:

```bash
CIBW_BUILD=cp312-manylinux_x86_64 CIBW_ARCHS_LINUX=x86_64 CIBW_MANYLINUX_X86_64_IMAGE=manylinux_2_34 \
CIBW_BEFORE_ALL_LINUX='dnf install -y wayland-devel libxkbcommon-devel dbus-devel pkgconf-pkg-config curl && curl -fsSL https://sh.rustup.rs | sh -s -- -y --profile minimal --default-toolchain 1.99.1' \
CIBW_ENVIRONMENT_LINUX='PATH="$HOME/.cargo/bin:$PATH"' \
CIBW_REPAIR_WHEEL_COMMAND_LINUX='auditwheel repair -w {dest_dir} {wheel}' \
CIBW_TEST_COMMAND_LINUX='python {project}/tools/release/smoke_installed_wheel.py' \
python -m cibuildwheel --platform linux --output-dir dist-manylinux dist/ui4me_core-1.0.0.tar.gz
``` The workflow builds the sdist and a pinned x86_64 manylinux 2.34 wheel, repairs native dependencies with `auditwheel`, validates artifacts, runs the installed `ui4me-host --version` check, then exposes downloadable CI artifacts. **It does not publish to PyPI.**

`manylinux_2_34_x86_64` requires glibc 2.34 or newer on consuming machines, compatible with Debian 13. The CI build selects one Python 3.12 builder but produces a `py3-none-manylinux_2_34_x86_64` wheel because there is no Python-native ABI dependency. Test installation with Python 3.10/3.12/3.13 on Debian 13, including an independent app.

## Clean installed-consumer smoke

```bash
python3 -m venv /tmp/ui4me-linux-wheel-test
/tmp/ui4me-linux-wheel-test/bin/python -m pip install dist/ui4me_core-1.0.0-*.whl
/tmp/ui4me-linux-wheel-test/bin/python -c 'import ui4me_core; print(ui4me_core.__version__)'
/tmp/ui4me-linux-wheel-test/bin/ui4me-host --version
/tmp/ui4me-linux-wheel-test/bin/ui4me-host doctor
```

Then install and launch a complete example from a directory outside the repository and perform native desktop verification. Build output must not need access to source, toolchain or checked-out assets at runtime.

## Publication decision

This repository does **not** include an automatic upload step. If the owner later chooses to publish, inspect `dist/` or the downloaded manylinux CI artifacts and verify their SHA256 hashes, license notices, `twine check`, source/ABI compatibility, clean installation and native tests first. Configure PyPI trusted publishing in its UI or use an approved upload command; do not embed credentials. Only after explicit user authorization, publish the exact verified wheel and source distribution.

## Using the installed package from an application manifest

Point `backend.program` at the virtual environment's interpreter (for example
`program = "/home/me/.venvs/app/bin/python"`) and launch with that environment's
`ui4me-host`. The host runs the named path (it does not resolve the venv symlink), so the
backend sees the environment's packages, including `ui4me_core`.
